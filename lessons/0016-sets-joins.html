Lesson 0016 · Logic

Which rows survive?

Joining two tables is set logic in disguise. Pick the join kind and you've picked which rows live, which die, and where the nulls appear.

⏱ 25–30 minutes, best on a wider screen ✎ No calculation, all logic 🎯 Win: choose the right Power Query join for a task, and predict the row count
New words
Set
A collection of distinct things: the set of customer IDs, the set of products sold in March.
Intersection
Items in both sets. The overlap in a Venn diagram.
Union
Items in either set (or both).
Key
The column used to match rows between tables, such as CustomerID.
Join (merge)
Combining two tables side by side by matching their keys. Power Query calls it Merge.
null
"No value here." Appears when a row had nothing to match.

Sets first

Take customers who ordered in January (set A) and in February (set B). Three questions come up all the time:

QuestionSet ideaVenn region
Who ordered in both months? (repeat customers)Intersection, A AND BThe overlap
Who ordered in either month? (active customers)Union, A OR BBoth circles
Who ordered in January but not February? (lapsed)Difference, A NOT BLeft circle minus the overlap

Counting the union is the overlap rule from Lesson 0012: |A| + |B| − |both|. Without subtracting, repeat customers get counted twice.

Joins are sets of rows

A join matches rows from two tables on a key. Power Query's Merge offers six join kinds, and each one keeps a different part of the Venn diagram (Microsoft Learn: Merge queries overview). The left table is the one you start the merge from, shown at the top of the Merge dialog.

Join kindKeepsTypical task
Left outer (default)All left rows + matchesAdd customer names to every order
Right outerAll right rows + matchesSame idea, other way round
Full outerEverything from bothReconcile two systems
InnerOnly matchesOrders with a known customer
Left antiLeft rows with no matchFind orders with an unknown customer ID (data quality)
Right antiRight rows with no matchFind customers who never ordered

Try it

Orders is the left table and Customers the right. Grey italic rows in the sources have no partner in the other table.

Experiments

  1. Start at Left outer. How many rows? Which order gets a null name, and why?
  2. Switch to Inner. Which row disappeared? What happened to total Amount?
  3. Try Left anti and Right anti. Which one would you send to the data team as a bug, and which to marketing?
  4. Full outer: count the rows. Does it equal Inner + Left anti + Right anti?

The row-count check

After any join, check the row count. With a left outer join where each key appears only once on the right, the result has exactly as many rows as the left table. If it has more, the right table has duplicate keys and some rows were copied. That's the subject of Lesson 0018.

Merge vs Append

Power Query has two ways to combine tables, and the exam likes to test which is which:

  • Merge joins side by side, matching keys. Columns are added.
  • Append stacks one table under another, such as January's sales under February's. Rows are added, and the columns should match.

Where you'll meet this

In Excel: =XLOOKUP(B2, Customers[CustID], Customers[Name], "not found") works like a left outer join for one column. Every order keeps its row, and unmatched ones show "not found".

In Power BI: Home → Merge queries in Power Query, then pick the join kind. After merging, you expand the new column to choose which right-table columns to bring in. PL-300 lists "merge and append queries" under preparing data.

In interviews: "How would you find customers who signed up but never ordered?" A strong answer: "A left anti join from Customers to Orders on CustomerID, which is the same as a right anti if Orders is on the left. Or in SQL, a LEFT JOIN where the order ID IS NULL."
